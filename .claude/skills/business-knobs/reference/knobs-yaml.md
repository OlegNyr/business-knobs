# `knobs.yaml` — справка по формату

Исходник разработчика; контрактом не является (контракт — сгенерированный файл стенда,
`doc/contract/stand-file.adoc`). Живой пример с комментариями — `doc/guide/knobs-example.yaml`.

## Шапка

```yaml
service: orders                # имя сервиса = spring.application.name
stands: [dev, test, prod]      # на каждый стенд — свой knobs-<стенд>.json
dimensions:                    # измерения пути; порядок (без service) — порядок точности,
  service: { kind: registry }  #   его берёт библиотека, и места короткого пути; новое — в конец
  dc:      { kind: stand }
  tenant:  { kind: stand }
  segment: { kind: code, values: [MASS, PREMIUM, PRIVATE, VIP] }
```

`kind` — кто задаёт значения измерения для админки: `code` (этот файл, `values`), `stand`
(администратор на стенде), `registry` (другой справочник админки). На выбор значения `kind` не
влияет.

## Параметр

Ключ пишется лесенкой; узел, в котором есть хотя бы одно из служебных слов
(`name`, `description`, `type`, `list`, `allowed`, `min`, `max`, `pattern`, `format`,
`default`, `rules`, `deleted`) — параметр, всё выше — путь ключа. Сегменты ключа — kebab-case
(`read-timeout`, не `readTimeout`). Префикс `knobs.` занят.

| Поле | Обязательно | Что значит |
|------|-------------|------------|
| `name` | да (кроме `deleted`) | Название для админки |
| `description` | нет, но нужно | Зачем параметр и чем грозит неверное значение |
| `default` | да | Умолчание везде: все стенды, любой путь. Единственное место умолчания |
| `type` | когда не выводится | `boolean`, `string`, `integer`, `double`, `duration`, `date`. Обязателен при значении-подстановке и пустом списке |
| `list` | нет | `true` — список значений типа |
| `min`, `max` | нет | Границы для чисел, длительностей, дат |
| `allowed` | нет | Закрытый список значений |
| `pattern`, `format` | нет | Форма строки (проверяет только админка) |
| `rules` | нет | Правила по контексту (ниже) |
| `deleted` | нет | `true` — ключ снят; держится один релиз |

Файл читается по YAML 1.2 core: признак — только `true`/`false`, число — десятичное. Ключ,
повторённый в одном отображении, — ошибка.

Вывод типа из значения: `true/false` → boolean, `2` → integer, `2.5` → double, `10s`, `500ms`,
`5m` → duration, `2026-11-01` → date, иной текст → string, `[jpg, png]` → список по элементам.
Ловушки: дробный параметр со значением `10` без `type` станет целым, текст `10s` — длительностью;
`010`, `0x1F`, `yes`/`no`/`on`/`off` без `type` — ошибка (в YAML 1.1 это были бы число и признак).
Подстановка `${ИМЯ}` — только в скалярном значении, не в элементе списка.

## Правила

Места в пути — измерения шапки в объявленном порядке без `service`; для шапки выше это
`/dc/tenant/segment`.

```yaml
rules:                      # для всех стендов
  - value: 60s              # без when — везде
  - when: [/dc2]            # ЦОД dc2
    value: 15s
  - when: [/dc2/*/VIP]      # ЦОД dc2, сегмент VIP
    value: 20s
  - when: [/*/*/VIP]        # любой ЦОД, сегмент VIP
    value: 18s
rules:                      # по стендам
  dev:
    - value: 60s
  all:
    - when: [/dc2]
      value: 15s
```

- `*` — «любое значение»; хвост из `*` не пишется, последняя часть звёздочкой не бывает,
  пустое место (`/dc1//VIP`) — ошибка; путь из одних `*` — ошибка (для этого есть `default`).
- Именованная форма: `when: [{segment: VIP}, {dc: dc2, segment: MASS}]` — по именам измерений,
  порядку не важна. Её же можно смешивать с коротким путём в одном `when`.
- Значение измерения `kind: code` обязано быть из его `values` — в обеих формах.
- Сервис не пишется (правило относится к сервису файла); `"*/dc2"` со звёздочкой перед слешем —
  правило для всех сервисов, путь в кавычках.
- Побеждает самый точный подошедший путь: дальняя последняя часть, затем больше частей,
  затем правило своего сервиса, затем дальние места. Порядка у правил нет.
- Правило стенда без `when` перекрывает общие правила целиком.
- Правило без значения в выборе не участвует.
- Подстановка `${ИМЯ}` — только из переменных окружения процесса при чтении файла; при ней
  `type` обязателен.

## Что не параметр

- Секреты и учётные данные.
- Структурные ключи: `@ConditionalOnProperty`, `@Profile`, плейсхолдеры аннотаций и
  `${}` в `application.yaml`.
- Ключи без решения о значении («на всякий случай»).
