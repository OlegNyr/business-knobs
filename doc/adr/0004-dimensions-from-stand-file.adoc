= ADR-0004: Измерения пути и их порядок задаёт файл стенда
:revdate: 2026-10-17
:status: accepted

*Статус:* accepted (2026-10-17), пересмотрено в тот же день по итогам ревью перед релизом ·
*Контекст кода:* `ContextDimensions`, `StandFiles#dimensions`, `RuleEvaluator`, `ParameterSet`,
`ParameterSettingsProperties`, `Knobs.Builder#dimensions`, `SourceDimensions`

== Контекст

Значение параметра выбирается правилом с самым точным подошедшим путём. Точность зависит от
порядка измерений: чем дальше последняя названная часть пути, тем правило точнее. До выноса в
отдельную библиотеку порядок был зашит константой с измерениями одной предметной области, а
генератор понимал только путь `/ЦОД[/сегмент]`.

Первая редакция этого решения отдала порядок настройке сервиса (`knobs.dimensions`). Ревью
показало, что так порядок задаётся в двух местах — в исходном `knobs.yaml` (по нему генератор
разбирает пути) и в настройке пода — и расхождение ничем не ловится:

* забыли `knobs.dimensions` — по умолчанию `[dc]`, правила по `segment` из файла молча не
  действуют (строка TRACE);
* перечислили измерения без `dc` — молча гаснут все правила по ЦОД;
* другой порядок — молча другой победитель среди подошедших правил.

== Решение

*Порядок задаёт файл стенда; настройка сервиса нужна, только когда файл измерений не объявляет.*

. Измерения пути — секция `dimensions` файла стенда без `service`, в порядке объявления. Это
  те же объявления, по которым генератор разбирал пути правил, поэтому каждое измерение, которое
  может назвать правило файла, известно и в рантайме.
. `knobs.dimensions` (`KNOBS_DIMENSIONS`) и `Knobs.builder().dimensions(...)` — для файла без
  секции `dimensions` и для сервиса без файла. Заданные и расходящиеся с файлом измерения —
  отказ на старте с обоими списками, а не молча другой выбор. Без файла и без настройки
  измерение одно — `dc`.
. Порядок несёт снимок `ParameterSet`: все входы (группы, `Parameters`, OpenFeature,
  `Environment`, аварийная правка) видят один и тот же порядок.
. Правило с измерением вне порядка в выборе не участвует (TRACE с причиной); аварийная правка с
  таким измерением отбивается.
. `dc` — измерение пода: значение берётся из настроек пода (`knobs.dc`), а не из обращения.
. Генератор:
  * короткий путь `/dc2/*/VIP` — места по объявленным измерениям; пустое место (`/dc1//VIP`) —
    отказ, «любое значение» пишется `*`;
  * именованная форма `when: [{segment: VIP}]` — без привязки к позициям;
  * значение измерения `kind: code` сверяется с его `values` в обеих формах.

== Последствия

*Хорошее.*

* Одно место правды о порядке; расхождение невозможно молча.
* Типичному сервису настраивать измерения не нужно вовсе.

*Плохое.*

* Короткий путь привязан к позициям: измерение, вставленное в середину списка, сдвигает смысл
  уже написанных коротких путей. Проверка `values` ловит это только для измерений `kind: code`.
  Правило: новое измерение — в конец списка, а для правил по нескольким измерениям —
  именованная форма.
* Порядок теперь часть файла стенда: смена порядка — новая сборка сервиса, а не настройка пода.

== Отвергнутые альтернативы

* *Порядок только из настройки сервиса* (первая редакция). Два места правды, расхождения
  молчаливы — см. «Контекст».
* *Только именованная форма в исходном файле.* Надёжнее, но короткий путь `/dc2` — самая частая
  запись; запрет сделал бы файлы многословнее без выигрыша для правил по одному ЦОД.
